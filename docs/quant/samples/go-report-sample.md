## Disclosures

- **Fee source (F2)**: per-venue taker fees come from live exchange metadata, fetched at runtime and applied per trade. They are NOT part of the run hash (fee tiers are exchange-side facts), so a fee-tier change inside the window is not visible as a new run. No fee-table snapshot is stored at run start; the per-trade fee breakdown is persisted in `spread_evaluations` (profitable rows are kept indefinitely), and the observed effective rates are listed below.

|---|---|---|---|---|

| okx | 497 | 0.08 % | 0.08 % | 0.10 % |

- **Accrual / `since`**: data for a set exists only from its run start (`since`); no backfill. A changed run definition or strategy parameter starts a new run with fresh capital and a new `since`; earlier runs are listed per set but never mixed into a window. Comparisons between sets use only the common window.
- **Parameters**: only the run hash is stored, not the parameter values; the dates of parameter changes are the run starts listed per set. Any parameter chosen by looking at data may only use the tuning part (holdout restarts from a change).
- **Tuning vs holdout**: chronological, tuning = first third (min 7 days), holdout = rest (min 14 days, k = floor(holdout/7) <= 4 equal periods); boundaries are rounded up to UTC midnights so that equity at an edge is an end-of-day state. GO numbers are holdout only.
- **Tax model**: tax = rate x max(window total, 0), losses are not refunded; rates 15 % and 35 % shown, the verdict uses 35 %. Final tax position is open (G3, accountant).
- **Liquidation reserve**: non-USDT inventory is charged a flat 0.3 % exit cost (taker fee + half spread approximation, same as the paper conversion cost, N11); venue-specific spreads are not stored. It is subtracted from the headline.
- **Hedge**: no hedge cost is modelled; `hedged` is a reference, never the headline.
- **N1 shared alert gating**: paper trades fire on shared alerts; a route that opened its episode while only a smaller set held it in its top-N is not re-alerted for `all` (downward bias on `all` only; bounded by `alerts cap-excluded`).
- **N2 shared evaluation deadline**: timeouts hit all sets; the share is read from logs (supplied via the ops file), not from the database.
- **N3 equal split**: the same $ per set is split equally over its venues; smaller sets get deeper inventory per venue and idle capital sits on rarely used venues (shown as deployed vs idle capital).
- **N4 trade size**: realised average notional is shown per window; scaling claims must use it (the target notional is capped by the coin slot).
- **N5 MTM**: about half of the capital sits in alt inventory; MTM is shown separately and flagged when it dominates.
- **N6**: `membership_missing` is not persisted; supplied from logs when available.
- **N9 idle clock**: the slot idle clock resets on a restart (conservative; shows up as `coin_budget_exhausted`).
- **N10 stranded coin**: unseeded coin value at window end is shown; it is already inside the liquidation reserve.
- **N12 per-set heartbeat**: hours without a sweep come from `paper_cap_stats`; days with gaps are listed, nothing is removed.
- **N13 rolling deploy**: when a run replaced an earlier one, its first 10 minutes are excluded from the window.
- **Snapshots**: equity uses the last balance snapshot at or before each instant (hourly resolution in the query, daily after retention thinning); per-coin MTM for the ex-top-2-coins test is an approximation at that granularity.
- **Regime**: BTC volatility per period is not stored; regimes come from the ops file. Unknown or a single regime caps the confidence at `low`.
- **Concentration** is a filter inside one set (B14-style approximation, likely conservative); rebalance costs are attributed by asset and destination venue pro rata to trade notional.
