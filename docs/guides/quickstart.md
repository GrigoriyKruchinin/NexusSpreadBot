# Nexus: быстрый старт (для тех, кто не пишет код)

Этот гайд ведёт от нуля до первого алерта в вашем Telegram. Примерно 10–20 минут, если Docker уже
установлен. Английская версия коротко: [README.md](../../README.md).

## Что это такое

**Nexus Spread Scanner** — программа, которая смотрит цены криптовалют на нескольких биржах
(Binance, Bybit, Gate.io, KuCoin, OKX) и ищет **спред**: разницу цен одной и той же монеты на разных
биржах. Программа считает **чистый спред** — то, что останется после комиссий, проскальзывания и
стоимости перевода монеты между биржами. Найденные возможности она присылает в ваш Telegram.

Важно:

- **Nexus ничего не покупает, не продаёт и не выводит деньги.** Торговли и переводов в программе нет.
- Это **информационный инструмент, не финансовый совет**. Цифры — оценки, они могут устареть.
- Программа работает **на вашем компьютере** (или сервере), данные хранятся в **вашей** базе.

Термины, которые встретятся дальше:

- **Docker** — программа, в которой Nexus запускается как набор «контейнеров». Вам нужно только
  установить её и запустить.
- **make** — команда, которая запускает готовые действия (`make up`, `make logs`).
- **`.env`** — файл с вашими секретами: токен бота, пароль базы, ключи бирж. Его никому не показывайте
  и никуда не копируйте.
- **API-ключ** — пароль от биржи для программ. Нужен только для дополнительных данных (комиссии
  переводов, статус ввода/вывода). Без ключей Nexus тоже работает.

## Что нужно заранее

1. Компьютер, который будет включён всё время работы (ноутбук, который уходит в сон, будет давать
   пропуски в данных).
2. **Docker**: на Windows — Docker Desktop с WSL2, на Linux — Docker Engine с плагином Compose v2,
   на macOS — Docker Desktop. Проверка в терминале: `docker compose version`.
3. **make** и **Git**. На Windows используйте WSL (Ubuntu): `sudo apt install make git`.
4. Telegram на телефоне или компьютере.

## Шаг 1. Создайте бота в @BotFather

1. В Telegram найдите **@BotFather** (официальный бот Telegram для ботов, с синей галочкой).
2. Отправьте `/newbot`.
3. Введите имя бота (любое, например «Мой Nexus»).
4. Введите username бота: латиницей, должен заканчиваться на `bot`, например `my_nexus_alert_bot`.
5. BotFather пришлёт **токен** — строку вида `123456789:AAE...`. Скопируйте её.

Токен — это секрет: тот, у кого он есть, управляет вашим ботом. Не публикуйте его.

## Шаг 2. Выберите, куда приходят алерты

Есть два варианта.

**Вариант А — личный чат с ботом (проще, рекомендуется для начала).**

1. Найдите своего бота по username и нажмите **Start** (или отправьте `/start`).
2. Узнайте свой числовой id: напишите **@userinfobot** — он ответит вашим `Id`, например
   `123456789`. Это число (без минуса) и будет вашим `TELEGRAM_CHAT_ID`.

**Вариант Б — закрытый канал (для себя).**

1. Создайте в Telegram новый канал и сделайте его **приватным** (не публичным, без ссылки
   `t.me/...` для всех). Канал нужен только вам.
2. Откройте канал → настройки → **Администраторы** → **Добавить администратора** → найдите своего
   бота.
3. Дайте боту права **«Публикация сообщений»** (Post messages) и **«Редактирование чужих
   сообщений»** (Edit messages of others). Остальные права не нужны. Сохраните.
4. Узнайте id канала: перешлите любое сообщение из канала боту **@userinfobot** (или **@RawDataBot**).
   В ответе будет `Id` вида **`-1001234567890`**. Начинается с **минуса и `-100`**. Это и есть
   `TELEGRAM_CHAT_ID`.

Названия пунктов меню в Telegram иногда меняются, но смысл тот же.

> **Не делайте канал публичным.** Биржи запрещают публиковать их рыночные данные без письменного
> разрешения: OKX и KuCoin — прямо, у Binance риск высокий, у Bybit и Gate.io — серая зона. Закрытый
> канал только для вас — допустимо. Не продавайте
> доступ к каналу, не добавляйте рекламу и реферальные ссылки.

## Шаг 3. Ключи бирж (необязательно)

Без ключей Nexus работает в **публичном режиме**: цены и стаканы считаются, а комиссии переводов и
статусы ввода/вывода не читаются. Алерты менее точные. Ключи можно добавить сразу или позже.

Если создаёте ключ, соблюдайте **чеклист**:

- [ ] Право **«Чтение»** (Read) — включено.
- [ ] Право **вывода / вывода средств** (Withdraw) — **выключено**.
- [ ] Право **торговли** (Trade / Spot trading) — **выключено**.
- [ ] Белый список IP (IP whitelist / IP restriction) — **включите**, если биржа это предлагает. Это
  рекомендация, программа этого не проверяет.
- [ ] Для OKX и KuCoin пароль-фразу (passphrase) вы придумываете сами при создании ключа — запишите её.

Ключ и секрет нужно заполнять **вместе**. Для одной биржи либо оба поля, либо оба пустые.

**Что проверяет Nexus сам.** При запуске программа проверяет ключ: есть ли право вывода или торговли,
принимает ли биржа ключ. Ключ, который не прошёл проверку, **не используется**: эта биржа работает в
публичном режиме, а вы видите предупреждение в проверке настроек.

**Что проверить самим (важно).** **KuCoin:** Nexus проверяет права ключа, но не видит его белый список
IP. **Gate.io:** Nexus не видит права ключа; ключ Gate.io с правом торговли или вывода в обычном
режиме всё равно будет использоваться для чтения (Nexus никогда не отправляет ордера и выводы, но
утечка такого ключа опасна). Откройте настройки ключа на бирже и убедитесь вручную, что включено
только чтение, а вывод и торговля выключены, либо поставьте `KEY_POLICY_STRICT=true`, чтобы такой
ключ был отклонён.

**Ваши ключи остаются у вас.** Ключи API необязательны и только для чтения. Они читаются из вашего
локального файла `.env`, используются только для подписи запросов, которые отправляются напрямую в API
самой биржи, и никогда не записываются в журналы, не хранятся в базе данных, не отправляются в Telegram
и авторам. В Nexus нет телеметрии. Создавайте ключи **без права торговли и без права вывода**;
включайте ограничение по IP там, где биржа его предлагает. Тексты алертов (цены, спреды) попадают в
Telegram, который выбираете вы.

**Строгий режим (необязательно).** В `.env` можно поставить `KEY_POLICY_STRICT=true`. Тогда ключ,
который не прошёл проверку, останавливает запуск, нужен белый список IP, а биржи, где API не может
показать права (KuCoin по IP, Gate.io по правам), не подключаются. Для обычного использования не нужно.

Биржи могут не обслуживать некоторые страны. Ваша страна и правила биржи — ваша ответственность:
проверьте условия использования биржи для вашего региона.

## Шаг 4. Создайте файл `.env`

В папке проекта выполните:

```bash
cp .env.example .env && chmod 600 .env
```

Откройте `.env` в любом текстовом редакторе (блокнот подойдёт, но не текстовый процессор вроде Word)
и заполните **три обязательных** поля:

```dotenv
TELEGRAM_BOT_TOKEN=<токен от BotFather>
TELEGRAM_CHAT_ID=<ваш id: 123456789 или -1001234567890>
POSTGRES_PASSWORD=<пароль для базы, не короче 12 символов>
```

Пароль для базы можно сгенерировать командой `openssl rand -base64 32` и вставить результат. Если
оставить `POSTGRES_PASSWORD` пустым, `make up` сгенерирует его сам и запишет в `.env` (значение на
экран не выводится).

Ключи бирж вписываются в те же строки `*_API_KEY`, `*_API_SECRET` и `*_API_PASSPHRASE`. Пустые строки
не трогайте.

Не добавляйте в `.env` другие настройки (пороги, языки, биржи). Для этого есть файл
`config/nexus.toml`, см. раздел «Настройки» ниже.

## Шаг 5. Запустите

```bash
make up
```

Команда проверит `.env`, соберёт программу, применит миграции (создание таблиц базы), запустит всё и
подождёт, пока сканер будет готов. Первый раз это занимает несколько минут.

В конце появится строка `OK: stack is up`. Если нет — смотрите раздел «Если что-то не работает».

Проверьте состояние:

```bash
make ps                  # все сервисы в состоянии healthy; migrator — exited (0), это нормально
make logs s=scanner      # журнал сканера; выйти: Ctrl+C
make doctor              # полная проверка: настройки, база, миграции
```

Чтобы проверить Telegram, выполните `make doctor ARGS=--send-test`: в чат придёт тестовое сообщение.

Первый алерт может появиться не сразу: при пороге 0,3 % и $5 подходящие спреды бывают редко.

## Пример алерта

Так выглядит новый алерт по умолчанию, на английском (цифры выдуманы). Если в `config/nexus.toml` указано `[alert] language = "ru"`, текст будет
русским:

```text
🟢 ABC/USDT   +0.80 % net
Buy  Binance  100
Sell KuCoin  101
Net after fees/slippage: +0.80 % (≈ +$7.98 on $1,000)
Volume: up to $3,050 (≈ 30.5 ABC) by orderbooks
Transfer: BEP20 · fee 0.8 ABC (≈ $0.08) · ≈ 5 min (approx)
Withdraw Binance: ✅ open   Deposit KuCoin: ✅ open
Lifetime: just opened   ·   #7
```

Как читать:

- **net** — чистый спред после комиссий и проскальзывания. Чем больше, тем лучше, но это оценка.
- **Buy / Sell** — где покупать и где продавать, и цены.
- **Volume** — сколько можно примерно купить/продать по стаканам.
- **Transfer** — сеть для перевода монеты и её комиссия. Время перевода — примерное.
- **Withdraw / Deposit** — открыты ли вывод и ввод. Если закрыт, перевод сейчас невозможен.
- **Taker fee is an estimate** — комиссия без ключа взята оценочно.

Алерт по одной и той же возможности **обновляется** в том же сообщении, пока спред жив, и в конце
получает итог «Closed». Если за час пришло слишком много новых алертов, лишние объединяются в одно
сообщение «N more suppressed».

## Настройки

Настройки лежат в **`config/nexus.toml`** (открывается в обычном редакторе). Самые полезные:

| Что | Где | Значение по умолчанию |
|---|---|---|
| Язык алертов | `[alert] language` | `en` (поставьте `ru` для русского) |
| Минимальный чистый спред | `[spread] min_net_profit_pct` | `0.3` (%) |
| Минимальная чистая прибыль | `[spread] min_net_profit_usd` | `5` ($) |
| Обновлять алерт при изменении прибыли на | `[alert] update_min_change_pct` | `25` (%) |
| Не чаще, чем раз в N секунд | `[alert] update_min_interval_s` | `60` |
| Максимум новых алертов в час | `[alert] max_per_hour` | `30` |
| Биржи для сканирования | `[exchanges] enabled` | binance, bybit, gateio, kucoin, okx |
| Проверка свежести бэкапов | `[watchdog] backup_check_enabled` | `false` (оставьте, если не настраивали бэкапы) |

После изменения `config/nexus.toml` выполните `make up` снова: настройки «запекаются» в программу, и
команда пересоберёт её.

Свои настройки можно держать в файле `config/local.toml`. В git он не попадает и перекрывает значения
по умолчанию из `config/nexus.toml`. Пишите туда только то, что меняете, например язык алертов:

```toml
[alert]
language = "ru"
```

После правки выполните `make up` (настройки встраиваются в образ). Секреты сюда не пишите — они только в `.env`.

Текст для закреплённого сообщения в канале: `make pin-text ARGS="--lang ru"`.

## Если что-то не работает

| Что видно | Что сделать |
|---|---|
| `TELEGRAM_BOT_TOKEN пуст` или `должен быть…` | Заполните токен в `.env` (шаг 1), без пробелов и кавычек |
| `Telegram отклонил токен (401)` | Токен неверный или отозван: получите новый у @BotFather командой `/token` |
| `Чат не найден` | Для личного чата: отправьте боту `/start`. Для канала: добавьте бота администратором |
| `Бот не администратор канала` / `без прав` | В канале: Администраторы → бот → включите «Публикация сообщений» и «Редактирование чужих сообщений» |
| `Не удалось связаться с Telegram` | Проверьте интернет. Если Telegram в вашей стране заблокирован, нужен VPN |
| `ключ отклонён` / `PUBLIC mode` | Проверьте ключ, секрет и passphrase, срок действия. Пока биржа работает в публичном режиме |
| `ключ может ВЫВОДИТЬ` | Создайте **новый** ключ только на чтение и удалите старый |
| `База данных недоступна` | Запущен ли стек (`make up`)? Совпадает ли `POSTGRES_PASSWORD` с тем, с которым создана база |
| `В базе ещё нет схемы` / `Схема БД отстаёт` | `make migrate` (обычно `make up` делает это сам) |
| `port is already allocated` (только если вы включили необязательный порт базы) | Порт 5432 занят другим PostgreSQL или старым стеком `nexus-local` (`docker compose -p nexus-local down` остановит его, данные сохранятся). Остановите его или задайте `POSTGRES_HOST_PORT=15432` |
| Сканер не `healthy` | `make logs s=scanner`, затем `make doctor` |

Доступ к базе с вашего компьютера по умолчанию выключен. Чтобы включить (только `127.0.0.1`, не наружу):
`COMPOSE_FILE=docker-compose.yml:docker-compose.postgres-port.yml make up`, порт 5432 или
`POSTGRES_HOST_PORT`.

Общая диагностика: `make doctor`. Журнал одного сервиса: `make logs s=scanner` (другие сервисы:
`worker-alerts`, `worker-maintenance`, `beat`, `postgres`, `redis`).

## Обновление, остановка, сброс

- **Остановить:** `make down`. Данные сохраняются, при следующем `make up` всё продолжит работать.
- **Обновить:** `git pull`, затем `make up`. Изменения структуры базы применяются сами миграциями при каждом
  `make up`, данные сохраняются. Только база, созданная до 2026-10-25 (сжатие схемы S1-tool), не
  обновится: сохраните данные, если они нужны, и один раз сбросьте базу (`make reset-data`).
- **Сбросить данные:** `make reset-data`. Команда **удаляет базу и данные Redis** безвозвратно; она
  спросит, нужно ли напечатать `DELETE`. Выполняйте её только осознанно.

## Вопросы

Если шаг не получился, сначала запустите `make doctor` и посмотрите строки `[FAIL]` и `[WARN]`:
там написано, что исправить. Сообщения об ошибках и журналы не публикуйте целиком: в них могут быть
данные из `.env`, проверьте перед отправкой.
