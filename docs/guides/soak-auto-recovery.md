# Автовосстановление стека после перезапуска WSL / Windows и внешний сторож

Зачем это нужно. 24.10.2026 после `wsl --shutdown` Docker Desktop поднял базу и Redis, но все контейнеры приложения
упали сразу при старте (код 127, без логов). Причина (подтверждена по логам Docker Desktop): файл настроек
`config/nexus.toml` лежал в папке Ubuntu и подключался к контейнерам как «bind mount» (проброс папки с диска).
Docker Desktop пробрасывает такие папки только после того, как поднимется его связка с Ubuntu, а контейнеры он
перезапускает раньше. Теперь настройки зашиты в образ, а отдельный сторож на хосте дочищает остальное и шлёт
оповещение в Telegram, даже если все контейнеры мертвы.

Что уже сделано в коде (вам ничего делать не нужно): настройки в образе; скрипт `scripts/host_watchdog.sh`.
Развёртывание (пересборка образа и пересоздание контейнеров) выполняет оркестратор отдельно, после вашего «да».

Все шаги ниже делаете **вы** (нужны права Windows или `crontab`); я их не выполняю.

## Шаг 1. Docker Desktop стартует при входе в Windows
Docker Desktop -> Settings -> General -> включите **Start Docker Desktop when you sign in to your computer**.
Остальное (WSL 2 engine, интеграция с Ubuntu-22.04) уже включено.

## Шаг 2. Ubuntu стартует при входе в Windows (иначе cron-бэкап в 03:15 и сторож не работают)
Cron живёт внутри Ubuntu и работает, только пока дистрибутив запущен. Создайте задачу в Планировщике заданий Windows:
1. Win -> «Планировщик заданий» -> «Создать задачу» (не «простую»).
2. Общие: имя `Nexus WSL keepalive`; «Выполнять только когда пользователь вошёл в систему»; можно поставить «Скрытая».
3. Триггеры: «При входе в систему» (ваш пользователь).
4. Действия: программа `C:\Windows\System32\wsl.exe`, аргументы `-d Ubuntu-22.04 --exec /usr/bin/sleep infinity`.
5. Условия: снимите «Запускать только при питании от сети», если это ноутбук. Параметры: снимите «Останавливать задачу, если выполняется дольше 3 дней».
Эта задача держит Ubuntu включённой (она не засыпает) и поднимает его после каждой перезагрузки и входа.

Важно: пока вы не вошли в Windows, ни WSL, ни Docker Desktop не стартуют. После перезагрузки (обновления Windows) нужно один раз
войти в учётную запись; дальше всё поднимется само. Автовход без пароля снижает безопасность ПК, включайте его только осознанно.
Если ПК перезагрузился ночью и вы не вошли, об этом сообщит только внешний пульс (шаг 4).

`/etc/wsl.conf` с `[boot] command` не нужен: Ubuntu и так запускается этой задачей и Docker Desktop, а контейнеры
поднимает сам Docker (`restart: unless-stopped`).

## Шаг 3. Сторож на хосте (cron в Ubuntu, каждые 5 минут)
Что делает `scripts/host_watchdog.sh`: проверяет, что контейнеры работают и здоровы (проверка здоровья сканера = свежий
пульс обхода); остановленные контейнеры запускает командой `docker compose start` (без пересоздания); если стек не
поднимается или сканер «unhealthy» дольше двух проверок подряд (около 10 минут), присылает сообщение в Telegram
(не чаще раза в час), а когда всё восстановилось, пишет «healthy again». Токен бота читается из `.env` прямо в скрипте
и нигде не печатается. Ничего не пишет в базу.

В терминале Ubuntu:
```bash
mkdir -p ~/.local/state/nexus-host-watchdog
crontab -e
```
добавьте строку (путь как у вашей строки бэкапа):
```
*/5 * * * * /home/grisha/projects/NexusSpreadBot/scripts/host_watchdog.sh >> /home/grisha/.local/state/nexus-host-watchdog/watchdog.log 2>&1
```
Проверка: `tail -3 ~/.local/state/nexus-host-watchdog/watchdog.log` (через 5 минут должна быть строка `ok`).
Журнал растёт примерно на 15 КБ в сутки; раз в месяц можно очистить: `: > ~/.local/state/nexus-host-watchdog/watchdog.log`.

**Пауза на время работ** (деплой, ручная остановка контейнеров): `touch ~/.nexus-watchdog-pause`; вернуть: `rm ~/.nexus-watchdog-pause`.
Иначе сторож запустит намеренно остановленный контейнер. Не забудьте снять паузу.

## Шаг 4 (по желанию). Внешний пульс на случай, когда выключен весь ПК
Сторож на самом ПК не может сообщить, что ПК выключен. Для этого нужен бесплатный внешний сервис (например healthchecks.io):
сторож после каждой успешной проверки «стучится» на ваш адрес, а сервис шлёт письмо/Telegram, если стука нет. Ранее (23.10)
вы отложили это до VPS; решение остаётся за вами. Если включаете: положите адрес-пинг в файл `~/.nexus-heartbeat-url`
(`chmod 600`), и добавьте в crontab перед командой переменную: `HEARTBEAT_URL_FILE=$HOME/.nexus-heartbeat-url`
(в той же строке, как для бэкапа, см. [backups.md](backups.md)). Адрес секретный: не показывайте его в чате. Период на сервисе
поставьте 15 минут + запас 10 минут.

## Как повторить проверку D-01 (после развёртывания)
1. `docker compose -f docker-compose.local.yml ps -a` - все `Up (healthy)`, `migrator` `Exited (0)`.
2. В PowerShell: `wsl --shutdown`. Подождите 3-5 минут (Docker Desktop сам перезапустится).
3. В Ubuntu: `docker compose -f docker-compose.local.yml ps -a`. Ожидание: сканер, воркеры, beat поднялись сами
   (`worker-maintenance` может подняться на 5 минут позже: его папка статуса бэкапа подключается после Ubuntu; тогда его запустит сторож).
4. Telegram: «restarted ... now healthy» от сторожа допустимо. Сообщение `ALERT` через 10+ минут означает, что автовосстановление не сработало.
