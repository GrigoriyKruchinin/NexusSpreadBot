# Stage 1 — локальный запуск сканера (read-only)

Этот гайд готовит всё необходимое для запуска **Nexus Spread Scanner V1** на ноутбуке:
сканер следит за стаканами 5 бирж, считает чистый спред с учётом комиссий, проскальзывания
и стоимости перевода, и шлёт алерты в Telegram. **Бот ничего не покупает, не продаёт и не
выводит** — в V1 нужны только ключи «только чтение».

Порядок: Telegram-бот → `TELEGRAM_CHAT_ID` → API-ключи бирж (опционально, но желательно) →
`.env` → запуск.

> **Нет аккаунтов на биржах?** Сканер полностью работает без ключей — см. раздел
> [«Быстрый старт без ключей»](#быстрый-старт-без-ключей) ниже. Ключи можно добавить позже.

---

## Быстрый старт без ключей

Нужно только: Docker, Telegram-бот (разделы 1–2) и пароль для локальной БД.

```bash
cp .env.example .env && chmod 600 .env
openssl rand -base64 32            # скопируйте результат в POSTGRES_PASSWORD
```

В `.env` заполните **только три** значения, всё остальное оставьте как есть
(строки `*_API_KEY` / `*_API_SECRET` / `*_API_PASSPHRASE` — пустыми). Остальные настройки
(пороги, биржи, интервалы) лежат не в `.env`, а в файле `config/nexus.toml` — см. раздел 4:

```dotenv
TELEGRAM_BOT_TOKEN=<токен от @BotFather>
TELEGRAM_CHAT_ID=<ваш chat id>
POSTGRES_PASSWORD=<сгенерированный пароль, не короче 12 символов>
```

Запуск и проверка:

```bash
make up-local           # сборка и запуск (первый раз — несколько минут)
make ps-local           # через ~1 минуту все сервисы healthy, migrator — exited (0)
make logs s=scanner     # каждые ~10 с строка sweep_done
```

В Telegram придёт **🚀 Nexus Spread Scanner запущен**: у каждой биржи пометка 🌐 (публичные
данные) и число пар. Это подтверждает всю цепочку: сканер → очередь → worker → Telegram.

**Что работает без ключей:** тикеры, стаканы (REST и WebSocket), расчёт чистого спреда с
комиссиями и проскальзыванием, алерты, запись всех оценок в БД. Статусы вводов/выводов без
ключа публикуют KuCoin, Gate.io, Bitget и Binance (через публичную страницу); для Bybit, OKX и
MEXC их нет. По умолчанию (`SPREAD_REQUIRE_VERIFIED_TRANSFER=true`) алерты приходят **только**
по связкам с подтверждённым маршрутом перевода, поэтому без ключей Bybit/OKX/MEXC почти не
будут давать алертов. Комиссии без ключа помечаются **ℹ️ Комиссия тейкера оценочная**.

**Увидеть алерт быстрее** (при порогах 0.3 % / $5 их может не быть часами): временно
поставьте в `config/nexus.toml` в разделе `[spread]` `min_net_profit_pct = 0.05` и
`min_net_profit_usd = 0.5`, выполните `make up-local`, дождитесь сообщения **💹 Арбитражная возможность** и верните значения
`0.3` и `5` (снова `make up-local`).

**Посмотреть статистику в БД** (порт открыт только на 127.0.0.1):

```bash
docker compose -f docker-compose.local.yml exec postgres \
  psql -U nexus -d nexus -c "select status, count(*) from spread_evaluations \
  where evaluated_at > now() - interval '1 hour' group by 1 order by 2 desc;"
```

Остановка: `make down-local` (данные сохраняются). Когда появятся аккаунты — создайте
read-only ключи по разделу 3, впишите их в `.env` и снова выполните `make up-local`.

## 1. Создание Telegram-бота и `TELEGRAM_BOT_TOKEN`

1. В Telegram откройте **@BotFather** (проверьте синюю галочку верификации).
2. Отправьте `/newbot`.
3. Введите отображаемое имя, например `Nexus Spread Scanner`.
4. Введите username бота — должен оканчиваться на `bot`, например `nexus_spread_grisha_bot`.
5. BotFather пришлёт токен вида `1234567890:AAH...`. Это и есть **`TELEGRAM_BOT_TOKEN`**.

> ⚠️ Токен = полный контроль над ботом. Не отправляйте его никому, не коммитьте в git,
> не вставляйте в чат с ассистентом. Если токен утёк — в @BotFather: `/revoke` → выберите бота.

Рекомендуемые настройки в @BotFather (необязательно):
- `/setdescription` — описание бота.
- `/setjoingroups` → `Disable`, если бот будет писать только вам лично (защита от добавления в чужие группы).

## 2. Получение `TELEGRAM_CHAT_ID`

### Вариант A — личные сообщения (рекомендуется для начала)

1. Найдите своего бота по username и нажмите **Start** (или отправьте любое сообщение).
   Без этого бот не сможет вам писать.
2. Откройте в браузере (подставьте свой токен):
   ```
   https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates
   ```
3. В ответе найдите `"chat":{"id":123456789,...}` — число **`123456789`** и есть `TELEGRAM_CHAT_ID`.
   Если ответ `{"ok":true,"result":[]}` — отправьте боту ещё одно сообщение и обновите страницу.

### Вариант B — группа или канал

1. Создайте группу/канал и добавьте туда бота (для канала — как администратора с правом публикации).
2. Напишите сообщение в группу (в канале — опубликуйте пост).
3. Откройте тот же URL `getUpdates`. ID группы — **отрицательное** число, например `-1001234567890`.
   Минус — часть ID, копируйте его целиком.

> Если в группе бот не видит сообщений: @BotFather → `/setprivacy` → выберите бота → `Disable`,
> затем удалите и снова добавьте бота в группу.

## 3. API-ключи бирж (только чтение)

### Зачем ключи, если стаканы публичные?

Стаканы и тикеры сканер читает **без ключей**. Ключи «только чтение» нужны, чтобы:

- получать **статусы депозитов/выводов и комиссии сетей** (у Binance, Bybit и OKX эти данные
  доступны только с ключом). Без них сканер не может исключить «фальшивые» спреды, когда на
  одной из бирж закрыты вводы/выводы монеты — это главная причина ложных сигналов;
- в будущем — учитывать **ваш личный уровень комиссий** (VIP-tier).

Без ключей сканер работает, но связки с биржами без данных о переводах не алертятся
(они только записываются в БД как «unverified»).

> **Пример из первого запуска.** За 1,5 часа без ключей пришёл 21 алерт по ZIL и ONE:
> спред ~1 % держался десятки минут. Причина — на Binance нативные сети ZIL и ONE
> приостановлены, монету нельзя перевести, поэтому спред и не закрывается. С ключами
> сканер видит статус сетей и такие связки не алертит, а в Stage 1.5 ещё и автоматически
> отправляет их в карантин.

Ключи нужны для **5 основных бирж**: Bybit, Binance, OKX, Gate.io, KuCoin. MEXC и Bitget
(Stage 1.5) работают только в публичном режиме, **без ключей**: проверка политики ключей пока не
знает эти биржи и откажется запускать сканер, если для них задан ключ. HTX не поддерживается — биржа под санкциями.

### Общие правила безопасности (для всех бирж)

- ✅ Включайте **только чтение** (Read / Read-Only / General).
- ❌ **Никогда** не включайте: Trade, Withdraw, Transfer, Margin, Futures, Sub-account.
  Бот спроектирован так, что вывод средств невозможен в принципе, но ключ должен быть
  безопасен даже при утечке.
- Включите 2FA на каждой бирже — без него большинство бирж не даёт создать ключ.
- Сохраняйте `Secret` и `Passphrase` сразу — биржа покажет секрет **только один раз**.
- Привязка к IP: на ноутбуке IP обычно динамический, поэтому для read-only ключей в V1
  её можно не включать. В V2 (торговые ключи на VPS) привязка к IP будет **обязательной**.
- Создавайте **отдельный ключ под бота**, не переиспользуйте ключи других сервисов.

### 3.1 Bybit

1. Войдите на bybit.com → иконка профиля → **API**.
2. **Create New Key** → **System-generated API Keys**.
3. Тип: **API Transaction**, название: `nexus-scanner-readonly`.
4. Permissions: **Read-Only**. Не отмечайте ни одного пункта в разделах Orders/Trade/Assets
   с правом записи; **Withdrawal — выключено**.
5. IP restriction: можно оставить без привязки. Учтите: ключи **без IP-привязки Bybit
   может деактивировать через 3 месяца** — тогда создайте новый.
6. Подтвердите 2FA, сохраните:
   - API Key → `BYBIT_API_KEY`
   - API Secret → `BYBIT_API_SECRET`

### 3.2 Binance

1. binance.com → профиль → **Account → API Management**.
2. **Create API** → тип **System generated** (HMAC) → название `nexus-scanner-readonly`.
3. После создания нажмите **Edit restrictions** и убедитесь, что отмечено **только**
   **Enable Reading**. Все остальные (Spot & Margin Trading, Withdrawals, Universal Transfer,
   Futures и т.д.) — **выключены**.
4. IP access: **Unrestricted** допустимо только для read-only ключа.
5. Сохраните:
   - API Key → `BINANCE_API_KEY`
   - Secret Key → `BINANCE_API_SECRET`

> Binance.com недоступен в ряде юрисдикций. Если ваш аккаунт на региональной версии
> (Binance US / TR и т.п.) — сообщите, это другой API и потребует отдельного адаптера.

### 3.3 OKX

1. okx.com → профиль → **API** (API keys).
2. **Create V5 API key** → назначение: **API trading** (это просто тип ключа),
   название `nexus-scanner-readonly`.
3. Придумайте **Passphrase** (не путать с паролем от аккаунта) — запишите его, восстановить нельзя.
4. Permissions: только **Read**. **Trade** и **Withdraw** — не отмечать.
5. IP: можно оставить пустым. OKX может автоматически удалять ключи без IP-привязки после
   длительной неактивности — если сканер начнёт получать `Invalid API key`, создайте ключ заново.
6. Сохраните:
   - API Key → `OKX_API_KEY`
   - Secret Key → `OKX_API_SECRET`
   - Passphrase → `OKX_API_PASSPHRASE`

### 3.4 Gate.io

1. gate.io → профиль → **API Management** → **Create API Key**.
2. Тип: **API v4 Key**, название `nexus-scanner-readonly`.
   > Если появилась ошибка **«Please setup fund password (safepwd) first»** — сначала задайте
   > фонд-пароль: **Security Settings → Fund Password** (нужна 2FA), затем повторите.
3. Account Type: **Trading Account** (обычный ключ основного аккаунта).
   **Не выбирайте Testnet** — ключи тестовой сети на боевом API дают `INVALID_KEY`.
   Third-party account тоже не нужен.
4. Permissions: для **Spot Trading** и **Wallet** выберите **Read Only**.
   **Withdraw** — не включать. Остальные разделы — отключены.
5. IP whitelist: можно не указывать.
6. Сохраните:
   - Key → `GATEIO_API_KEY`
   - Secret → `GATEIO_API_SECRET`

### 3.5 KuCoin

1. kucoin.com → профиль → **API Management** → **Create API**.
2. Тип: **API Trading**, название `nexus-scanner-readonly`.
3. Придумайте **API Passphrase** — запишите его.
4. Permissions: только **General** (это чтение). **Spot Trading, Margin, Futures, Transfer,
   Withdrawal** — **не отмечать**.
5. IP restriction: можно не включать.
6. Сохраните:
   - API Key → `KUCOIN_API_KEY`
   - API Secret → `KUCOIN_API_SECRET`
   - Passphrase → `KUCOIN_API_PASSPHRASE`

### 3.6 MEXC (Stage 1.5)

> Пока **не выполняйте** этот раздел: ключ MEXC/Bitget будет отклонён проверкой политики ключей (только публичный режим).

1. mexc.com → профиль → **API Management** → **Create API Key**.
2. Название (Notes): `nexus-scanner-readonly`.
3. Permissions: отметьте **только просмотр** — в разделах Account и Spot пункты вида
   **View account details / View order details** (Read). Пункты с правом записи
   (**Trade**, **Withdraw**, **Transfer**, Futures) — **не отмечать**.
4. IP binding: можно не указывать. У MEXC ключи без IP-привязки действуют ограниченный срок
   (обычно 90 дней) — после истечения создайте новый.
5. Подтвердите 2FA, сохраните:
   - Access Key → `MEXC_API_KEY`
   - Secret Key → `MEXC_API_SECRET`

### 3.7 Bitget (Stage 1.5)

> Пока **не выполняйте** этот раздел: ключ MEXC/Bitget будет отклонён проверкой политики ключей (только публичный режим).

1. bitget.com → профиль → **API Management** → **Create API** →
   **System-generated API key**.
2. Название: `nexus-scanner-readonly`.
3. Придумайте **Passphrase** (8–32 символа, буквы и цифры) — запишите его, восстановить нельзя.
4. Permissions: **Read-only** (только чтение). **Trade**, **Withdraw**, **Transfer** — **не
   отмечать**.
5. IP binding: можно не указывать (ключ без привязки может быть ограничен по сроку — при
   ошибке `Invalid API key` создайте новый).
6. Подтвердите 2FA, сохраните:
   - API Key → `BITGET_API_KEY`
   - Secret Key → `BITGET_API_SECRET`
   - Passphrase → `BITGET_API_PASSPHRASE`

> **Bitget, единый торговый аккаунт (UTA).** Сканер запрашивает вашу комиссию через
> классический эндпоинт `common/trade-rate`. Если аккаунт переведён в UTA и запрос не
> проходит, бот использует публичную ставку Bitget (0,2 %) и помечает её в алертах как
> оценочную — это безопасно (комиссия завышена, а не занижена), но часть сигналов может
> отсеяться.

> Если какую-то биржу вы не используете — оставьте её переменные пустыми, сканер будет
> работать с ней через публичные данные. Чтобы полностью отключить биржу — уберите её из
> `[exchanges] enabled` в `config/nexus.toml`.

## 4. Настройка `.env` и `config/nexus.toml`

**Что где лежит.** В `.env` — только секреты и значения, которые нельзя коммитить (токен бота,
chat id, пароли, URL Redis/Celery, API-ключи бирж, `KEY_POLICY_STRICT`). Все остальные
настройки — в файле `config/nexus.toml` (он в git, с комментариями; значения в нём равны
значениям по умолчанию). Приоритет: переменная окружения > `config/nexus.toml` > значение в
коде. Имя ключа в файле = префикс переменной (маленькими буквами) + поле: `SPREAD_MIN_NET_PROFIT_PCT`
→ `[spread]` `min_net_profit_pct`. Секрет или неизвестный ключ в `config/nexus.toml` — сканер
**откажется запускаться** и назовёт файл, ключ и строку (само значение в ошибке не показывается).

> **Важно после обновления: строки с настройками в старом `.env` ведут себя по-разному.**
> Если `.env` содержит строки с настройками (`SPREAD_*`, `SCANNER_*`, `PAPER_*`,
> `EXCHANGES_ENABLED`, `LOG_LEVEL`, `DIGEST_*`, `POSTGRES_DB/USER/PORT` и т. п.):
> - **в docker-стеке (`make up-local`) они молча НЕ действуют**: контейнеры не читают `.env`, а
>   `docker-compose.local.yml` больше не передаёт в них настройки. Любое нестандартное значение
>   из такой строки нужно **перенести в `config/nexus.toml` до перезапуска**, иначе оно пропадёт и
>   сервис возьмёт значение из файла;
> - **при запуске на хосте** (без docker) такие строки, наоборот, перекрывают файл
>   (приоритет: переменная окружения > `.env` > `config/nexus.toml` > значение в коде). Если
>   значение задано в окружении, оно заменяет значение файла целиком (для списков и словарей —
>   без слияния).
>
> Чтобы увидеть, какие настройки у вас остались в `.env`, выполните `make check-env-settings`
> (печатает только **имена**, значения не показываются; она же вызывается из `make up-local`).
> После переноса значений удалите эти строки из `.env`. При старте сканер, воркеры, планировщик
> и миграции пишут в лог событие `settings_loaded` со списком **имён** настроек, взятых из
> окружения (`env_overrides`), и хэшем итоговых настроек (`settings_hash`): он нужен, чтобы
> отчёт о результатах ссылался на точный набор настроек запуска (`make logs s=scanner`).

1. В корне проекта:
   ```bash
   cp .env.example .env
   chmod 600 .env
   ```
   Файл `.env` уже в `.gitignore` — в git он не попадёт. Агент Claude настроен так, что
   **не читает** `.env`.

2. Откройте `.env` в редакторе и заполните:

   ```dotenv
   # --- Telegram ---
   TELEGRAM_BOT_TOKEN=1234567890:AAH...
   TELEGRAM_CHAT_ID=123456789

   # --- PostgreSQL (локально придумайте любой надёжный пароль) ---
   POSTGRES_PASSWORD=<длинный случайный пароль>

   # --- Биржи (список бирж — в config/nexus.toml, [exchanges] enabled) ---
   BYBIT_API_KEY=...
   BYBIT_API_SECRET=...
   BINANCE_API_KEY=...
   BINANCE_API_SECRET=...
   OKX_API_KEY=...
   OKX_API_SECRET=...
   OKX_API_PASSPHRASE=...
   GATEIO_API_KEY=...
   GATEIO_API_SECRET=...
   KUCOIN_API_KEY=...
   KUCOIN_API_SECRET=...
   KUCOIN_API_PASSPHRASE=...

   # MEXC и Bitget (Stage 1.5): ключи НЕ задавайте. Проверка политики ключей отклоняет
   # запуск (код выхода 3), если для биржи без политики задан ключ. Добавьте "mexc","bitget"
   # в config/nexus.toml ([exchanges] enabled) и оставьте MEXC_* / BITGET_* пустыми.
   ```

   Случайный пароль можно сгенерировать так: `openssl rand -base64 32`.

3. Параметры стратегии лежат в `config/nexus.toml` (уже выставлены по вашим ответам, менять не
   обязательно; после правки файла выполните `make up-local`). В таблице — имя переменной
   (его же можно задать в окружении, оно перекроет файл):

   | Переменная | Значение | Смысл |
   |---|---|---|
   | `SPREAD_MIN_NET_PROFIT_PCT` | `0.3` | Минимальный чистый профит, % |
   | `SPREAD_MIN_NET_PROFIT_USD` | `5` | Минимальный чистый профит, $ (оба условия обязательны) |
   | `SPREAD_REFERENCE_NOTIONAL_USD` | `1000` | Объём сделки для расчёта проскальзывания по стакану |
   | `SPREAD_ALERT_COOLDOWN_S` | `600` | По одной связке приходит **один алерт на эпизод**. Этот интервал — минимальная пауза между первыми алертами разных эпизодов одной связки (если спред то пропадает, то появляется) |
   | `ALERT_REALERT_GROWTH_PCT` | `50` | Повторный алерт в рамках того же эпизода — только если чистая прибыль выросла на N % от последнего алерта |
   | `SPREAD_MAX_GROSS_SPREAD_PCT` | `20` | Спреды выше — подозрительные (разные токены с одним тикером / делистинг), не алертятся |
   | `SPREAD_REQUIRE_VERIFIED_TRANSFER` | `true` | Алертить только связки, где подтверждено, что монету можно вывести с биржи покупки и завести на биржу продажи. Неподтверждённые всё равно считаются и пишутся в БД (в дайджесте — как «unverified»). `false` — вернуть алерты с пометкой ⚠️ |
   | `SPREAD_TRANSFER_TAX_PCT` | `{"LUNC": 1.5, "USTC": 1.5}` | Налог сети на перевод (в % от суммы), которого нет в комиссии вывода биржи. У Terra Classic с августа 2026 сжигается 1,5 % каждого перевода — поэтому «вечный» спред LUNC ~0,8 % на деле убыточен |
   | `SPREAD_MAX_UNVERIFIED_GROSS_SPREAD_PCT` | `5` | Более строгий предел, если не подтверждены маршрут перевода **и** адрес контракта токена |
   | `EPISODE_CLOSE_GAP_S` | `300` | «Эпизод» возможности — непрерывный период, пока связка прибыльна. Он закрывается, если N секунд не было прибыльной оценки (связка не каждый проход попадает в проверку, поэтому короткие пропуски не разрывают эпизод) |

   | `QUARANTINE_WINDOW_H` / `QUARANTINE_MAX_EPISODES` | `6` / `5` | «Мерцающие» мёртвые связки: если за окно набралось `QUARANTINE_PERSIST_MIN` минут неподтверждённого спреда суммарно или 5 таких эпизодов — карантин |
   | `PAPER_LATENCY_MS` | `2000` | Через сколько мс после обнаружения связка перепроверяется по свежим REST-стаканам: «пережила» ли она задержку исполнения. Бумажная сделка исполняется по этим же стаканам |
   | `PAPER_ENABLED` | `true` | Бумажная торговля: каждый алерт «исполняется» виртуально, без доступа к биржам |

Одна строка добавляет набор: `all;excl_conditional;excl_gateio=-gateio`. Ошибка в значении останавливает сканер при старте. Сейчас на soak четыре набора | **Правило накопления:** данные набора копятся только с момента его добавления, задним числом ничего не считается; удалённый набор перестаёт копиться, строки остаются |

   | `DIGEST_ENABLED` / `DIGEST_TIME` / `DIGEST_TZ` | `true` / `09:00` / `Europe/Moscow` | Ежедневный дайджест в Telegram за последние 24 часа |

   | `TELEGRAM_EVENT_MAX_AGE_S` | `300` | Системное сообщение (биржа недоступна/восстановилась, старт/стоп) старше этого не отправляется, чтобы не вводить в заблуждение |

## 5. Запуск и проверка

```bash
make up-local          # собрать и запустить весь стек
make ps-local          # статус контейнеров — все должны быть healthy
make logs s=scanner    # логи сканера
```

Что должно произойти:
1. Поднимаются `postgres` и `redis`, затем `migrator` применяет миграции и завершается.
2. Стартуют `scanner`, `worker-alerts`, `worker-maintenance`, `beat`.
3. В Telegram приходит сообщение **🚀 Nexus Spread Scanner запущен** со списком бирж.
4. При появлении спреда, проходящего фильтры, придёт алерт **💹 Арбитражная возможность**.

### Как читать алерт

- **⚠️ Маршрут перевода не подтверждён** — появляется, только если вы выключили
  `SPREAD_REQUIRE_VERIFIED_TRANSFER`: сканер не смог подтвердить, что монету можно вывести с
  биржи покупки и завести на биржу продажи. Проверьте статус депозитов/выводов вручную.
- **ℹ️ Комиссия тейкера оценочная** — комиссия взята из справочника ccxt, а не персональная.
  С ключами подтягивается ваша реальная комиссия: для Binance, Bybit и Gate.io — сразу, для
  OKX — по конкретной паре, когда она становится кандидатом на алерт (кэш 6 часов).
- Все суммы рассчитаны для объёма `SPREAD_REFERENCE_NOTIONAL_USD` с учётом глубины стакана.
- **💹 Повтор №N: спред растёт** — тот же эпизод, но прибыль выросла минимум на
  `ALERT_REALERT_GROWTH_PCT` %; в строке «🔁 Net was …» — прибыль на момент прошлого алерта.
- **🏁 Возможность закрылась** (без звука) — эпизод, по которому был алерт, закончился: сколько
  он длился, пиковая прибыль и «⚡ Survived execution latency» — была ли связка ещё прибыльна
  при перепроверке через `PAPER_LATENCY_MS` после обнаружения (✅ — успели бы исполнить).
- **🚫 В карантин отправлено связок** — связка признана «мёртвой» и на `QUARANTINE_TTL_H` часов
  (по умолчанию 24) исключена: по ней нет алертов и не запрашиваются стаканы. Причины:
  - спред без подтверждённого маршрута перевода держится или повторяется: за
    `QUARANTINE_WINDOW_H` часов (6) суммарно `QUARANTINE_PERSIST_MIN` минут (15) или 5
    эпизодов — типичная картина, когда вывод монеты приостановлен (ZIL/ONE);
  - ввод/вывод монеты отключён на одной из бирж.

  Карантин снимается досрочно, как только при обновлении метаданных маршрут перевода
  подтверждается. Все связки, ушедшие в карантин за один проход, приходят одним сообщением;
  если «мёртвая» связка снова уходит в карантин по той же причине, сообщение повторяется не
  чаще раза в неделю.

  Снять карантин вручную (например, вы сами проверили, что вывод работает):
  `docker compose -f docker-compose.local.yml exec redis redis-cli --scan --pattern
  'nexus:quarantine:*'` — список, затем
  `docker compose -f docker-compose.local.yml exec redis redis-cli DEL 'nexus:quarantine:ZIL/USDT|binance>okx'`.

### Бумажная торговля (симуляция)

Бот **ничего не покупает и не переводит**. На каждый отправленный алерт он через
`PAPER_LATENCY_MS` берёт свежие стаканы и считает, что было бы при реальной сделке на
`PAPER_TRADE_NOTIONAL_USD`: покупка на одной бирже, одновременная продажа монеты из
инвентаря на другой. Когда инвентарь на бирже заканчивается, симулируется перевод
(самая дешёвая подтверждённая сеть, реальная комиссия вывода, деньги заблокированы на
`PAPER_REBALANCE_DELAY_MIN`). Результаты (сделки, пропуски с причинами, переводы, балансы)
пишутся в БД и попадут в ежедневный дайджест: прибыль от арбитража, стоимость переводов,
переоценка инвентаря (MTM), капитал и доходность. Реальный ребаланс по-прежнему делаете вы
вручную.

### Ежедневный дайджест

Каждый день в `DIGEST_TIME` (часовой пояс `DIGEST_TZ`) приходит **📊 Daily digest** за
последние 24 часа:
- **эпизоды**: всего / подтверждённых / неподтверждённых / ушедших в карантин; сколько
  «пережили» задержку `PAPER_LATENCY_MS`; медиана и максимум длительности; топ-5 связок по
  пиковой прибыли (⚡ — пережила задержку, 🐢 — нет);
- **бумажная торговля**: сделки и пропуски по причинам, прибыль и стоимость переводов за
  сутки; с начала — итог P&L = арбитраж − переводы + переоценка (MTM), капитал и ROC.
  Строка **🛡 Hedged** — результат без ценового риска инвентаря (арбитраж − переводы): так
  выглядел бы P&L, если бы запас монет был захеджирован. Именно он показывает, работает ли
  сам арбитраж; MTM — это колебания цены монет, которые вы держите;
- **карантин**: новые и активные связки;
- **биржи**: аптайм (доля успешных запросов) и покрытие статусов переводов.

Дополнительно:
- **условные биржи** (по умолчанию Bybit и Gate.io, список `CONDITIONAL_VENUES`): итоги по эпизодам и
  бумажному P&L даны дважды — «все» и «без условных». Строка «Условные биржи» показывает список.
  Итог «без условных» — это оценка-фильтр, а не замер (точные цифры дают наборы бирж);
- **наборы бирж** (`[paper] venue_sets`): по строке на каждый набор — P&L и капитал набора. Строка
  «простой» — доля времени, когда набор не считал. Набор с простоем 100 % — выключен или сломан: сообщите;
- строка **«Набор X перезапущен»** — набор пересоздан (другой список бирж, капитал или параметры). Он начинает
  новый отсчёт (`since`), старые данные остаются, но в сравнение не входят.

По этим цифрам принимается решение GO/NO-GO по отчёту B15 part 2 (`todo.md`, M3).

### Сторож (watchdog)

Сторож работает в контейнере `worker-maintenance` по расписанию и присылает сообщения в Telegram:
- **сканер молчит** — давно не было прохода по биржам; и сообщение о восстановлении;
- **набор бумажной торговли молчит** — набор не пишет данные дольше `paper_set_stale_h` (по умолчанию 3 ч).
  Набор, молчащий дольше `paper_set_retire_h` (168 ч), считается убранным из конфига и больше не алертит;
- **бэкап**: нет файла статуса, бэкап не удался, копия на диск C: не сделана или бэкап старше 26 часов.

**Важно (D-09):** сторож работает на том же компьютере. Если выключен весь ПК или WSL, он молчит. Поэтому
проверяйте дайджест каждое утро: нет дайджеста к ~09:30 — значит авария. Подробности в
[backups.md](backups.md).

### Ручное управление списком пар

- `[scanner] symbols_whitelist = ["BTC/USDT", "ETH/USDT"]` в `config/nexus.toml` — сканировать **только** эти пары.
- `[scanner] symbols_blacklist = ["ZIL/USDT"]` — никогда не сканировать эти пары (действует на все
  биржи и сильнее whitelist).
- Формат — как в алерте: `ТИКЕР/USDT`, список в кавычках через запятую. После изменения перезапустите стек
  (`make up-local`). Автоматический карантин работает по связкам (пара + направление
  биржа→биржа), а blacklist — по паре целиком и бессрочно.

При порогах 0.3 % / $5 алертов может не быть часами — это нормально для ликвидных пар.
Для проверки цепочки можно временно поставить в `config/nexus.toml` `min_net_profit_pct = 0.05`
и `min_net_profit_usd = 0.5` (раздел `[spread]`), перезапустить (`make up-local`) и потом вернуть значения.

Остановка: `make down-local` (данные в БД сохраняются в Docker volume).

## 6. Частые проблемы

| Симптом | Причина / решение |
|---|---|
| Нет сообщения о старте в Telegram | Не нажали **Start** у бота; неверный `TELEGRAM_CHAT_ID`; для группы — забыли минус |
| `401` / `Invalid API key` в логах биржи | Опечатка в ключе/секрете, не тот passphrase (OKX, KuCoin), ключ истёк/удалён (ключи без IP-привязки) |
| `451` / `restricted location` от Binance | Гео-блокировка Binance.com в вашем регионе — уберите `binance` из `[exchanges] enabled` в `config/nexus.toml` |
| Контейнер `scanner` unhealthy | `make logs s=scanner` — чаще всего нет сети или биржа ограничила частоту запросов |
| Ноутбук уснул — алертов нет | Отключите сон на время работы или дождитесь V2 (VPS). Если ПК выключен, сторож тоже молчит: проверьте утренний дайджест. См. [backups.md](backups.md) (раздел «Тест на неделю») и [soak-fresh-stack.md](soak-fresh-stack.md) |

## 7. Чек-лист перед запуском

- [ ] Бот создан, токен в `.env`, боту нажат **Start**
- [ ] `TELEGRAM_CHAT_ID` в `.env`
- [ ] Ключи бирж созданы **только с правом чтения**, вывод выключен
      (Bybit, Binance, OKX, Gate.io, KuCoin). Ключи MEXC и Bitget **не создавайте**: пока для них
      нет проверки политики, сканер откажется стартовать с такими ключами (только публичный режим)
- [ ] **Проверка ключей автоматическая, флагов подтверждения нет.** Сканер сам читает права ключа.
      Если ключ может выводить/переводить средства, торговать, слишком широкий или его не удалось
      проверить, сканер **не использует этот ключ вообще**: биржа работает в публичном режиме, в логе
      громкое предупреждение, в Telegram при старте одна строка «Ключ НЕ использован». Остальные биржи
      не затрагиваются. Привязка ключа к IP **настоятельно рекомендуется**, но не требуется
- [ ] **KuCoin и Gate.io:** их API не показывает привязку к IP (KuCoin) и права по группам (Gate.io);
      сканер предупреждает и продолжает. Убедитесь вручную: у ключа только право чтения
- [ ] **Строгий режим (необязательно, для своей установки):** `KEY_POLICY_STRICT=true` в `.env`.
      Отклонённый ключ останавливает запуск (код 3), привязка к IP обязательна, а биржи, свойства
      ключа которых API не показывает (KuCoin, Gate.io), не принимаются. Старые переменные
      `KEY_POLICY_*_ATTESTED` и `KEY_POLICY_IP_BINDING_WAIVED` больше не действуют: их можно удалить
      из `.env` (`make check-setup`/`nexus check` напомнит). **На сервере/VPS** включайте строгий режим
- [ ] `.env` заполнен (только секреты), в нём нет строк с настройками, права `600`, в git не попал (`git status` его не показывает)
- [ ] `make up-local` → все сервисы healthy → пришло сообщение о старте
