# S1-tool: ручная E2E-проверка (около 30 минут)

Цель: убедиться на живом тестовом боте, что образ, алерты (NEW/UPDATE/CLOSED), русский язык,
закреп и системные сообщения работают. Секреты никому не показывать: ни токен, ни содержимое `.env`,
ни скриншоты с ними. В отчёте они не нужны.

Нужны: Docker, `make`, тестовый бот (@BotFather) и **приватный тестовый канал**, где бот админ.
Никаких торговых ключей. Публичный режим достаточен.

## 1. Сборка образа без config/local.toml (N-2, часть 1)
1. Убедитесь, что файла нет: `ls config/` (должен быть только `nexus.toml`). Если `local.toml` есть, переименуйте: `mv config/local.toml config/local.toml.off`.
2. `make up` (сборка не должна падать, хотя `local.toml` нет).
3. Файл в образе: `docker compose --profile tools run --rm check ls /app/config`. Ожидание: только `nexus.toml`.

## 2. Сборка образа с config/local.toml (N-2, часть 2)
1. Создайте `config/local.toml` с таким содержимым (больше ничего):
   ```toml
   [alert]
   language = "ru"
   ```
2. `make up` (пересборка обязательна, файл запекается в образ).
3. `docker compose --profile tools run --rm check ls /app/config`. Ожидание: `local.toml` и `nexus.toml`.
4. Файл не должен попасть в git: `git status` не показывает `config/local.toml`.

## 3. Тестовый бот и канал
1. В `.env` (редактируйте сами, мне не показывать) должны быть `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` тестового бота и приватного канала. Подробности: `docs/guides/quickstart.md`.
2. После правки `.env` снова `make up`.

## 4. Проверка настроек
`make doctor` (это `nexus check`). Ожидание: Telegram OK, база OK, миграции OK. Предупреждения про биржи без ключей в публичном режиме нормальны.
Тестовое сообщение: `make doctor ARGS=--send-test`. Ожидание: сообщение пришло в канал.

## 5. Старт и алерты
1. `make ps`: все сервисы healthy.
2. `make logs s=scanner` и смотрите канал. Алерты могут появиться не сразу (минуты, зависит от рынка).
3. Ожидание:
   - сообщение **NEW** при появлении спреда;
   - потом то же сообщение **редактируется на месте** (UPDATE), а не приходит новым;
   - при исчезновении спреда то же сообщение меняется на **CLOSED**.
4. Если за 30 минут алертов нет, это не обязательно баг. Напишите в отчёте, сколько ждали.

## 6. Русский язык
Сообщения алертов должны быть на русском (из `local.toml`). Затем уберите `local.toml` (`mv config/local.toml config/local.toml.off`), `make up`, и сообщения должны вернуться на английский. Верните файл обратно, если он вам нужен.

## 7. Текст для закрепа
`make pin-text ARGS="--lang ru"` выведет текст дисклеймера. Скопируйте его в канал и закрепите. Проверьте, что текст читается и форматирование не сломано.

## 8. Системное сообщение
Проверьте любое системное сообщение (не алерт спреда). Самое простое: `make doctor ARGS=--send-test` из шага 4, либо `docker compose stop scanner`, подождать несколько минут (сторож может прислать сообщение о простое), затем `docker compose start scanner` (сообщение о восстановлении). Не используйте `down -v` и `reset-data`.
Ожидание: сообщение на нужном языке, без битой разметки.

## Что прислать в ответ (без секретов)
- Для шагов 1-8: OK / не OK и одна строка, что видели.
- Вывод `ls /app/config` из шагов 1 и 2.
- Скриншот или текст одного NEW, UPDATE и CLOSED (токены и id чата замазать).
- Были ли сообщения в канале дублями вместо редактирования.
- Любые ошибки из `make logs s=scanner` (только строки ошибок).
